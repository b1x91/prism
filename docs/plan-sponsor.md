# 후원 기획 (2026-10-15 논의, 아직 만들지 않음)

> 이름은 '구독'이어도 성격은 **후원** — 회원이 운영비(서버·코드 서명 등)를 나눠 내는 것. 기능을 돈으로만 잠그지 않는다.

## 정해진 것 (사용자 결정)

- **결제:** 법인에 붙은 **페이앱(PayApp)** 정기결제. 사람이 확인하지 않고 자동으로 돌아가야 한다 (0절 자동화 원칙).
- **후원자 혜택:**
  1. 후원 배지·머리 테두리 (사이드바·회원 페이지·랭킹)
  2. 피스 배율 · 상점 할인 (지금의 특별회원 혜택과 같은 틀, `RATES`·`SPECIAL_DISCOUNT`)
  3. 코치 리포트 먼저 열기 — 코치 리포트는 등급(정회원 이상)으로도 열리고, 후원자는 등급과 상관없이 열린다
- **시점:** 지금 당장 하지 않는다. 회원이 모이고 코치 리포트가 실제로 자주 채워지는 걸 본 뒤.

## Riot 정책 (2026-10 확인한 내용)

[Developer API Policy](https://support-developer.riotgames.com/hc/en-us/articles/22698698001939-League-of-Legends):
- 무료로 쓸 수 있는 부분이 반드시 있어야 한다 → 앱·웹 기능은 모두 무료, 후원은 꾸밈·배율·먼저 열기만.
- 유료 부분은 새 정보·통찰을 더한 것이어야 한다 → 코치 리포트는 규칙 기반 분석(`coachOf`).
- 구독·후원·현금화 안 되는 앱 내 화폐(피스)는 허용 방식. 가격이 불공정한지는 Riot 이 판단.
- 앱이 비공식 경로(LCU)를 쓰므로, 시작 전에 Riot 개발자 포털에 한 번 문의한다. **[검증필요]**

## 만들 때의 구조 (안)

```
페이앱 정기결제 → 결제 결과 알림(웹훅) → Worker /pay/payapp
  → 서명·금액 확인 → D1 sponsors(member_id, plan, paid_until, last_tx)
  → 혜택 판단: paid_until > 지금 이면 후원자
결제 실패·해지 → paid_until 이 지나면 자동으로 혜택 끝 (사람 손 없음)
```

- 후원자 여부는 **서버(D1)가 진실**. 디스코드 '후원자' 역할은 봇이 생기면 거꾸로 맞춘다 (선택).
- 결제창은 웹(`przm.web.app`)에서만 연다. 앱에서는 웹으로 보내는 링크만 (스토어 판 정책 [검증필요]).
- 회원과 결제를 잇는 값: 결제 요청에 회원 ID 를 실어 보내고 웹훅에서 돌려받는다. **[검증필요]** 페이앱 정기결제가 이런 사용자 값(var1 등)과 웹훅(feedbackurl)을 어떻게 주는지.
- 숫자는 한 곳에서: 후원 금액·배율·할인 → `server/src/roles.ts` 옆 `SPONSOR` 표.
- 개인정보 처리방침에 결제 기록(회원 ID·금액·날짜, 카드 정보는 페이앱만 가짐) 추가.
